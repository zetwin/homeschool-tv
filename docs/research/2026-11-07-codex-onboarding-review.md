## Codex's report
**Verdict: Not ready.** The timetable will leave much of the week without lessons, data changes can disappear between devices, and the family API exposes and accepts changes to private data without sign-in.

1. **Program — most likely to hurt the first week.** The family JSON has no `school` field, so the app fills in its default timetable. That timetable has 18 program periods a week, but only five child-visible lessons are ready for its starting units; many other periods will say the lesson is not made yet. The schedule also uses the same Year 7 program for every child, regardless of school level. It inserts a separate exam after each unit, but the 39-week count ignores exams: the seven subjects need 737 periods including exams, against 702 available. Homework entered for an earlier date disappears from the child’s To do list, and the two-week lookahead can miss a test due after a long break. **Smallest fix:** set a workable plan for each child’s year, count exam periods, and keep overdue homework visible. [schedule.js](../../.live/channel/views/schedule.js:33) · [curriculum.js](../../.live/channel/curriculum.js:84) · [student.js](../../.live/channel/views/student.js:72)

2. **Data and uptime.** Settings saves replace whole `kids` or `school` objects. If a child marks homework done while a parent edits the timetable, the later request can overwrite the earlier change with stale data. Saves fail silently; when the server is unreachable, the device keeps a local copy that a later refresh can replace. There is no backup. A damaged JSON file can crash the server on a GET, and a malformed lesson scene can throw while rendering and blank that lesson. The Mac going to sleep takes the server and media offline; the app’s wake request applies to the viewing device, not the Mac. **Smallest fix:** back up the data file, report failed saves, merge individual changed fields, validate lesson scenes, and keep the Mac awake with a stable network address. [store.js](../../.live/channel/views/store.js:93) · [serve.mjs](../../.live/tools/serve.mjs:38) · [app.js](../../.live/channel/app.js:333)

3. **Security — fix before family use.** `/api/state` has no sign-in for reads or writes, and the server listens on all network interfaces. The browser does the sign-in check; passwords and PINs remain plain text in the shared data and parent screens. The exam screen also displays the PIN. Changing passwords alone does not protect the API. **Smallest fix:** require server-side sign-in and role checks for every API request, and privately rotate any starter credentials. Before any other family uses this, add per-family data isolation, hashed passwords, and secure hosting. [serve.mjs](../../.live/tools/serve.mjs:45) · [parent.js](../../.live/channel/views/parent.js:39) · [exam.js](../../.live/channel/views/exam.js:60)

4. **Lessons.** The requested `node tools/check-lesson.mjs` run on `dev` reports **0 of 7 pass** because the in-progress opening edits lack voice files. The separate `.live` check also reports **0 of 7 pass**: lessons are missing required opening or ending parts, and several videos lack required status and follow-up. The Spanish pronunciation guidance has not been checked by a Spanish speaker; the Colombia climate notes flag weakly sourced figures and no local review. **Smallest fix:** finish and record the openings, review the facts with appropriate readers, and hold unreviewed clips until the live checker passes. [check-lesson.mjs](../../.live/tools/check-lesson.mjs:1) · [Spanish research notes](../../docs/research/2026-11-06-spanish-lesson-1.md:38) · [Colombia climate notes](../../docs/research/2026-11-06-colombia-climate.md:94)

5. **Tests and exams.** The question handlers provide tap alternatives for drag tasks, but there is no real-iPad test; typed word and written answers need the iPad keyboard. Word marking accepts any typed answer containing the expected word, so “not hinge” can score as correct for “hinge.” The advertised one-attempt exam rule is not enforced, and answers save only when the exam ends. Lesson tests also lack the written or spoken explanation required by the rules. **Smallest fix:** use exact answer matching, save exam answers as they change, enforce one attempt, and add an explanation task. [questions.js](../../.live/channel/views/questions.js:92) · [exam.js](../../.live/channel/views/exam.js:98) · [student.js](../../.live/channel/views/student.js:278)

6. **iPad and parent setup.** The app can be added from Safari to each iPad’s Home Screen; it has no offline service worker, so it still depends on the Mac being awake. Apple documents the Safari “Add to Home Screen” flow and says Safari traffic does not need a separate local-network permission prompt. A changed Mac IP can leave a saved icon pointing at the old address. The app also has one shared parent login, so it cannot show which of the two parents made a change. **Smallest fix:** reserve the Mac’s network address, install from Safari on each iPad, and agree on shared-parent use until separate logins exist. [manifest.json](../../.live/channel/manifest.json:6) · [Apple iPad web app setup](https://support.apple.com/en-gb/guide/ipad/ipad8f1f7a29/ipados) · [Apple local-network documentation](https://developer.apple.com/documentation/Technotes/tn3179-understanding-local-network-privacy?changes=_2%2C_2)

I inspected only the family data’s shape; no names, passwords, or PIN values are included here. No files were changed.
